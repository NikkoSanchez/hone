Pair Plan

A local review surface for agent-built plans — where every human thought stays attached to the exact work it is about.

Prototype status Review me

Click any outlined block, or select text inside one, to pin a comment to that target.

01North star

Make feedback a first-class artifact.

The plan, the review state, and the response back to the agent should remain local, durable, and inspectable.

02MVP promise

Queue now. Send once.

Do not make every click an agent turn. Let the reviewer batch precise updates, then deliver one coherent envelope.

02 / The loop

Human review becomes structured input.

Pair Plan is a stable local review application around an agent-edited HTML artifact. Pair Plan owns navigation, annotations, queue state, history, and transport; the artifact owns only the reviewed content. The agent patches that content incrementally instead of regenerating the application shell.

01 Agent writes

Patches only the artifact content at a known local file path; the Pair Plan shell remains stable.

02 Reviewer points

Clicks a block or selects a text range inside the rendered plan.

03 Queue builds

Several comments, decisions, and layout fixes wait together.

04 Agent polls

One long-lived poll receives the envelope and resumes work.

Target + queue contract

Every item carries the artifact revision, a stable anchor, an optional selected-text quote, nearby-context hash, the reviewer’s instruction, and a replacement key. If a reload makes the target ambiguous, Pair Plan marks it unresolved instead of silently attaching it to the wrong content.

03 / Runtime shape

One small Bun process owns the loop.

Use Bun to serve a stable plain-HTML/TypeScript review shell, proxy the artifact, watch local changes, and expose a minimal session protocol. Keep the browser talking to one loopback-only origin so the agent can run it as a normal command.

Proposed local topologylocal-only by default
Bun runtime

One process serves HTML, watches artifacts, persists sessions, and runs the TypeScript entrypoint.

Plain TypeScript UI

DOM modules own the stable shell. React stays deferred until state synchronization proves painful.

Split transport

SSE carries browser reload/presence; the agent long-polls for feedback and POSTs replies.

App-owned state

Path-keyed sessions live in one inspectable local directory with bounded cleanup.

06 / Build sequence

Ship the handoff in four narrow slices.

Each slice should leave a usable review loop behind, so we can test the agent interaction before adding more editor surface.

1
Confined session + stable shell

Bun server, loopback bind, canonical realpath, allowlisted artifact root, origin/host checks, app state directory, and the plain-TypeScript shell.

2
Precise annotation model

Revisioned anchors, selected-text quotes, context hashes, queue keys, rebase attempts, and an explicit unresolved state.

3
Split handoff protocol

Agent long poll, browser SSE, delivery acknowledgement, compact revision reply, presence, and end-session semantics.

4
Recovery + optional inboxes

Ambiguous-anchor fixtures, restart recovery, layout warnings, export, and end-to-end protocol tests.

Assumption

The agent can keep one foreground long poll attached to its active turn, so the app does not need a cloud callback.

Resolved

The browser uses SSE for reload/presence; the agent uses long poll for feedback and POST for acknowledgements and replies.

Acceptance rule

A target that cannot be relocated confidently after a revision is shown as unresolved and is never silently rebound.
